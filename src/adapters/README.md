# `src/adapters` — port implementations

| Folder     | Used by                                               | Backed by                                                                                                                                                                                                                                                                                                                 |
| ---------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tauri/`   | The desktop app                                       | Tauri plugins (`@tauri-apps/*`) and the community oauth plugin (`@fabianlars/tauri-plugin-oauth`): settings, logs, HTTP, database, the archive files (`TauriArchiveStore`) and the Steam sign-in (`TauriSignInGateway`: the oauth plugin runs the one-shot loopback listener, the opener plugin opens the system browser) |
| `browser/` | The desktop app and the browser dev mode (`pnpm dev`) | Browser APIs that ship in releases: the zstd Web Worker (`WorkerCompressor`)                                                                                                                                                                                                                                              |
| `dev/`     | Tests and the browser dev mode (`pnpm dev`)           | Memory (including the archive store, `MemoryArchiveStore`), Web Storage, sql.js, synthetic deadlock-api and a fixture Steam sign-in (`FixtureSignInGateway`)                                                                                                                                                              |

The composition root (`src/main.tsx`) picks the `tauri/` set or the `dev/` set with `isTauri()`; the compressor of `browser/` is the same in both. It reaches the development entry point (`dev/dev-environment.ts`) only in development builds, so release builds contain none of `dev/` ([ADR 0006](../../docs/adr/0006-development-code-out-of-releases.md)).

There is no adapter for the account: the linked account is a row of the app database, which `services/linked-account.repository.ts` reads (it implements the `AccountSource` port). The two environments differ in how the player links it. The desktop app, `pnpm dev:desktop` included, signs in through Steam's real page in the system browser. The browser dev mode has no listener and no Steam: its `FixtureSignInGateway` plays both parts, and answers a moment after the page is "opened" with the callback of the synthetic account, and the fixture HTTP client confirms it the way Steam does (once), so the sign-in flow checks and links it like a real one. Tests use the same gateway, and `StaticAccountSource` (a fixed account) where a service only needs an account id.

## Rules

- May import `ports/` and `core/` only (enforced by ESLint).
- Only `tauri/` (and `src/main.tsx`) may import `@tauri-apps/*` and `@fabianlars/tauri-plugin-oauth`.
- `console` is allowed in `dev/` only, where the console is the destination.
- `browser/` holds what uses browser APIs without being specific to Tauri, and so ships in releases, unlike `dev/`. A worker file is reached by its URL (`new Worker(new URL(…, import.meta.url), { type: 'module' })`), never imported, so this layer does not depend on `src/workers/`.
- One adapter per file, named `<name>.adapter.ts`, implementing exactly one port.
- Adapters stay thin: they do not wrap failures in `AppError` and do not validate the data they read. The failures of the underlying technology (a full disk, a plugin error…) propagate as they are; the service wraps them in an `AppError` and validates the data against the schema of `core/`. The exceptions are documented on their port: the HTTP client reports its transport failures as `AppError` (only the adapter can tell a timeout from a network failure or an oversized body), the logger never fails (a line it cannot write is dropped: there is nowhere left to report it), and the worker compressor reports its failures as `AppError`s (errors cross the worker boundary as text, so only the adapter can classify them): `invalid_payload` for data its codec could not read, `storage` for a broken compressor. The one tolerance is the Web Storage adapter, which reads stored text it cannot parse as "nothing saved".
- Every plugin permission an adapter needs must be granted in `src-tauri/capabilities/default.json` and justified there or in an ADR (least privilege). The `fs` plugin reaches the archive folder only: its scope is `$APPLOCALDATA/archive` and `$APPLOCALDATA/archive/**` (the folder itself and its content), and it is never granted as `fs:default`. The Steam sign-in is just as narrow: the webview may start and stop the listener and receive its event (`oauth:allow-start`, `oauth:allow-cancel`, `core:event:allow-listen`, `core:event:allow-unlisten`), and open Steam's login page and no other URL (`opener:allow-open-url`, restricted to `https://steamcommunity.com/openid/login*`; never `opener:default`).
